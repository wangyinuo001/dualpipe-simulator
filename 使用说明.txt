启动现场演示

在这个文件夹打开终端，执行：
python3 demo.py
Windows 可执行：python demo.py
浏览器将自动打开 http://127.0.0.1:8765 。关闭终端或按 Ctrl+C 会停止服务。
需要 Python 3.9 或更新版本。现场界面和调度器只使用 Python 标准库，不需要安装额外依赖；旧版静态画图脚本仍需要 matplotlib。
若端口被占用，可以运行：python3 demo.py --port 8766

课堂操作：上下同屏对照

页面上半部分为 1F1B，下半部分为简化双向调度；每组左侧显示实际调度源码，右侧显示 GPU 计算与通信资源和逐步生成的任务时间轴。两组使用相同参数和资源模式，共用仿真时钟和时间轴尺度。界面按共同时间顺序合并两种方法的执行记录，保留各自同一时刻内的动作顺序，不按各自的播放百分比同步。

点击“运行并播放”，随后可以“下一步”“上一步”，或以默认 30×“同步播放”。同步播放按共同仿真时钟连续推进，时间间隔与播放间隔成比例，不按代码步骤数量计时。单步按钮仍用于细看同一时刻内的代码动作。点击“先完成时刻”可直接观察一组结束、另一组仍执行的状态。某种方法先完成时，对应面板会显示完成时间；另一种方法继续执行。“看完整结果”跳到最终状态，在页面底部显示总完成时间、加速比和计算空闲比例。“找一次重叠”定位任一方法中计算与通信重叠的步骤。“突出微批”只改变任务图的强调范围，不改变共同时间或跳过事件。

从课堂演示.py 运行后打开的时间轴.html 使用同样的布局，直接载入已计算的记录；网页服务首页可以重新修改参数运行。右上角链接保留完整时间轴和图片导出。基础组、通信增加组、微批增加组均应使用相同资源模式比较。

实现与数据口径

原始新版本保留在上级目录的 DualPipe_仿真程序与实验结果_20261108.zip 中。本界面复用其中 dualpipe_a/simulator.py，不替换调度策略；每次点击运行都会在 Python 后端重新调度并执行 validate_schedule。没有用预先写好的结果来代替运行。

这版 dualpipe 是“简化双向优先级调度”：就绪任务优先级为通信、B、F、W，不是 DeepSeek 官方 DualPipe 调度的逐项复现。模型包含相邻流水线通信，没有真实 Attention/MLP、MoE All-to-All、SM 或显存带宽竞争，也不计算显存占用。应以这个范围介绍，不能将结果称为官方 DualPipe 的实测性能。

总完成时间：最后一个事件的结束时刻。
计算空闲比例：1−总计算任务时间/(GPU 数×总完成时间)，包括等待通信的时间，不单独等同于首尾流水线气泡。
通信覆盖比例：通信占用的 GPU 端点时间中，与同一 GPU 计算时间重叠的比例，不等同于总耗时减少比例。
加速比：1F1B 总完成时间/简化双向总完成时间。小于 1 表示简化双向在该条件下更慢。

技术核对时可执行：python3 -m unittest discover -s tests -v
原有测试和静态图导出依赖 matplotlib，可先安装 requirements.txt。
